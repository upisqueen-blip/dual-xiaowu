## 第三方应用接入：确权方案 + 两份文档

**背景**：Codex 脉动（ISV，桌面应用）要上小悟墨水屏，引出"账号怎么打通、我怎么知道他推过来的是谁"的问题。经多轮澄清，确立了通用接入模型。

### 关键认知（已与用户对齐）
- **平台永不代查用户大模型账户**：OpenAI/DeepSeek 均无"第三方按用户查余额"的开放接口；代查需持有用户 token，泄露风险不可接受，且违反各家条款。
- **确权只解决"数据归谁、上哪块屏"**，不解决"怎么取数"。取数在 ISV 侧（最好用户本机），平台只收结果。
- **MAC 只能做标识，不能做凭证**（可伪造/可枚举）。现有 `device_id(=MAC) + device_token` 双件套方向正确。
- **数据库不打通**，只走 API：关系层打通（授权记录），存储层隔离。直连库 = 无法审计 + 越权。
- **通用性来源**：确权协议与终端形态解耦——一套状态机（pending→approved→active→revoked），四种终端只决定"码怎么给用户看"。
- **授权必须显性**：看得懂（应用名+人话权限+目标设备）、点得到（允许/拒绝二选一，禁止默认勾选/自动通过）、撤得掉（同一入口可撤销）。属个保法单独同意要求。

## 线上部署后 /admin 404（排查工具）
- 现象：服务器上 `/`（众创）、`/center`（运营）正常，「双屏内容配置」→ `/admin` 报 404。本地 `8094/admin` 与 `8101/admin` 均 200，故问题在服务器侧配置。
- 链路：浏览器 `/admin` → pc-console rewrite（`XIAOWU_CONTENT_CONSOLE_URL`）→ content-console-cn（`basePath=/admin`）。任一环缺失即 404。
- 新增诊断脚本 `scripts/diag-admin-404.sh`：检查两个 .env 关键变量、`.next/routes-manifest.json` 是否含 `/admin` 前缀（判断是否旧构建）、端口监听、`8094/admin`→`8101/admin`→`/health` 逐级状态码，带 A~E 判读表。用法 `bash scripts/diag-admin-404.sh https://域名`。
- `apps/pc-console/next.config.mjs`：`XIAOWU_CONTENT_CONSOLE_URL` 现在自动剥尾部 `/admin`，避免填成 `http://host:8094/admin` 时拼出 `/admin/admin/...` 导致 404。
- **部署铁律**：改过 `next.config.*`（basePath / rewrites / redirects）必须重新 `npm run build`，只重启进程不生效。

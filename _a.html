第三方应用把内容推到小悟墨水屏的接口集合。 接入顺序固定为四步：**签发凭证 → 确权绑定 → 交付数据 → 推送上线**。 关键约束： 1. 所有接口用 `X-App-Key` 鉴权，值就是开发者后台签发的 App Token（只显示一次）。 2. 推送前必须先完成确权：设备必须被**用户本人**显性授权给你的应用，否则返回 `403 pairing_required`。 平台不接触用户的大模型账号与凭证，也无法代查任何第三方额度——取数在你那边完成，这里只接收结果。 3. 推送是**异步**的：`202` 只代表已入队，真实「已显示 / 失败」请查 `/events` 或配置 webhook。 4. 屏幕是墨水屏：400×300、无动画、字号 ≥18px、单屏信息 ≤6 条；同一内容不要高频重推（耗电、伤屏）。 错误统一形如 `{"error": "code", "message": "人话说明"}`，`error` 可用于程序判断，`message` 可用于展示。

Base URLhttp://127.0.0.1:8104
鉴权X-App-Key
编码application/json · UTF-8
错误体{"error","message"}

权限 scopes

device.content.write写入内容（推送卡片、申请绑定码）
device.read读取设备能力与规格
device.event.read读取设备事件回执

接入四步

1签发凭证后台签发 App Token（X-App-Key）
2确权绑定pairing/start → 用户确认 → pairing/{code} 拿 device_id
3交付数据静态页 / 你的 HTTP 端点，二选一
4推送上线POST /content，202 入队，events 或 webhook 回收执
post/openapi/v1/pairing/start① 确权绑定

申请一次性绑定码

把返回的 `display_code` 展示给用户（如「K7M-2QP」），让他在小悟后台『授权管理』里输入并点「允许」。 码默认 10 分钟有效、只能用一次。授权成功后轮询 `GET /openapi/v1/pairing/{code}` 拿 `device_id`。

示例

curl -X POST "$BASE/openapi/v1/pairing/start" \
  -H "X-App-Key: $APP_TOKEN" -H "Content-Type: application/json" \
  -d '{"label":"Codex 脉动","scopes":["device.content.write"]}'

请求体示例

{
  "label": "Codex 脉动",
  "scopes": [
    "device.content.write"
  ]
}

响应

201绑定码已创建
{
  "code": "K7M-2QP",
  "display_code": "K7M-2QP",
  "expires_in": 600,
  "expires_at": "2026-11-02T12:00:00+00:00",
  "confirm_path": "/pair?code=K7M-2QP",
  "confirm_hint": "请让用户登录小悟后台并打开『授权管理』，输入上方绑定码确认",
  "label": "Codex 脉动",
  "scopes": [
    "device.content.write"
  ]
}
401App Token 无效
{
  "error": "invalid_app_key",
  "message": "invalid app key"
}
403缺少 scope
{
  "error": "missing_scope",
  "message": "missing scope: device.content.write"
}
get/openapi/v1/pairing/{code}① 确权绑定

轮询绑定结果

建议每 3 秒轮一次，拿到 `approved / denied / expired` 任一终态就停。 只有 `approved` 才返回 `device_id`，也只有此时才能推送。

示例

curl "$BASE/openapi/v1/pairing/K7M-2QP" -H "X-App-Key: $APP_TOKEN"
参数位置必填说明
codepath是绑定码，必须是本应用申请的（跨应用查询返回 404）

响应

200当前状态
{
  "code": "K7M-2QP",
  "status": "approved",
  "device_id": "DC:DA:0C:44:6D:D4",
  "grant_id": "grt_7f2c1a",
  "expires_at": "2026-11-02T12:00:00+00:00"
}
404码不存在或不属于该应用
{
  "error": "pairing_code_not_found",
  "message": "pairing code not found"
}
get/openapi/v1/devices/{device_id}② 设备信息

查询设备能力

示例

curl "$BASE/openapi/v1/devices/DC:DA:0C:44:6D:D4" -H "X-App-Key: $APP_TOKEN"
参数位置必填说明
device_idpath是确权成功后拿到的 device_id（就是设备 MAC）

响应

200设备能力
{

post/openapi/v1/devices/{device_id}/content③ 内容推送

推送 e-ink 卡片

异步接口：返回 `202` 只代表已入队，设备下次唤醒才会拉取并显示。 **两个前置条件**（缺一就失败）： 1. 该设备已被用户授权给你的应用，否则 `403 pairing_required`； 2. `template` 必须是平台已注册且启用的模板，`data` 要满足该模板的必填字段，否则 `400 / 422`。 当前已注册模板：`notice-card`（title, content）、`daily-schedule`（title, items）、`homework-list`、`vocabulary-card`、`care-reminder`。

示例

curl -X POST "$BASE/openapi/v1/devices/DC:DA:0C:44:6D:D4/content" \
  -H "X-App-Key: $APP_TOKEN" -H "Content-Type: application/json" \
  -d '{"template":"notice-card","screen":"A","data":{"title":"API 额度","content":"剩余 $42.10 · 6 天后重置"},"expires_in_seconds":900}'
参数位置必填说明
device_idpath是

请求体示例

{
  "template": "notice-card",
  "screen": "A",
  "data": {
    "title": "API 额度",
    "content": "剩余 $42.10 · 6 天后重置"
  },
  "expires_in_seconds": 900
}

响应

202已入队
{
  "task_id": "9f8c2b1a4d5e6f708192a3b4",
  "status": "queued"
}
400模板不存在或已停用
{
  "error": "unknown_template",
  "message": "unknown or disabled template"
}
403设备未授权给本应用（需先确权）
{
  "error": "pairing_required",
  "message": "该设备尚未授权给此应用。请先调用 POST /openapi/v1/pairing/start"
}
404设备不存在
{
  "error": "device_not_found",
  "message": "device not found"
}
422data 缺少模板必填字段
{
  "error": "template_validation_failed",
  "message": "template_validation_failed: missing title"
}
get/openapi/v1/devices/{device_id}/events④ 回执与事件

拉取设备事件回执

用于确认内容是否真的显示、失败原因是什么。需要 `device.event.read` scope。 生产环境更推荐配置 webhook（`device.event` / `task.displayed` / `task.failed`）避免轮询。

示例

curl "$BASE/openapi/v1/devices/DC:DA:0C:44:6D:D4/events" -H "X-App-Key: $APP_TOKEN"
参数位置必填说明
device_idpath是

响应

200事件列表（按时间倒序）
[
  {
    "event_type": "task.displayed",
    "data": {
      "task_id": "9f8c2b1a4d5e6f708192a3b4"
    },
    "occurred_at": "2026-11-02T03:20:11+00:00",
    "received_at": "2026-11-02T03:20:19+00:00"
  }
]

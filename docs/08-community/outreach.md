# 开源作者邀请 · 操作手册

面向的对象：GitHub 上做墨水屏 / 电子纸的独立作者与小团队。

前提先说清楚：**我们不送硬件**。合作的基础是「你的东西真的能跑在量产设备上，并且有真实用户看得到」，
而不是一份样品。所以整条路径是：

```
筛选 → 定向贡献（在他自己的仓库里留下真实改动） → 邀请上架 → 上线后看数据 → 再谈订阅分成
```

免费阶段不承诺收入；订阅与分成规则另发。任何话术里都不要替平台许诺具体金额。

---

## 一、筛人：`scripts/find_eink_projects.py`

一个人工翻 GitHub 一晚上能看 20 个仓库，脚本 5 分钟能扫近千个，再按口径收敛到几十个。

```bash
# 默认口径：近 180 天活跃 + MIT/Apache/GPL 系许可 + 有驱动/数据/出图能力
python scripts/find_eink_projects.py

# 更严：只要 MIT / Apache-2.0 / GPL，不看 LGPL / BSD / MPL
python scripts/find_eink_projects.py --strict --days 90

# 只看中文项目
python scripts/find_eink_projects.py --queries "墨水屏 in:name,description,readme" \
                                    "电子墨水 in:name,description,readme"
```

输出到 `output/eink-scan/`：`.md`（给人看）、`.csv`（进表格跟进）、`.json`（二次处理）。

### 三道硬门槛

| 门槛 | 判据 | 为什么 |
| --- | --- | --- |
| 近 N 天有**人**提交 | 默认分支最近 6 条提交里能找到非 bot 作者 | `pushed_at` 经常是 dependabot 刷出来的；只看它会捞到一堆只剩自动更新的仓库 |
| 许可明确 | `license.spdxId` 在白名单内 | 没有 LICENSE ≠ 开源；「公开可读」默认保留所有权利，不能拿来分发 |
| 与墨水屏相关 | 仓库名 / 简介 / topics 命中，或仓库里有屏驱动代码 | 只在 README 里列过硬件型号的项目会被排掉 |

进名单之后再看两件事，用于排序和分级：**近 N 天 issue 有没有回复**（作者还在不在）、
**近 N 天有没有 PR 在动**（有没有别人也在参与）。

### 三条能力信号（至少中 1 条）

只认**仓库里真实存在的代码文件**，不认 README 里的说法：

- **驱动** `driver`：`epd*.c` / `gxepd*` / `ssd16xx` / `uc81xx` / `il03xx` / `waveshare` / `inkplate`
- **数据** `data`：`http*` / `api*` / `client*` / `fetch*` / `sync*` 之类代码文件，或 `api/` 目录
- **出图** `render`：`image*` / `draw*` / `render*` / `gfx*` / `canvas*`

三条都命中的人最好谈：他自己就有一整套「取数 → 排版 → 上屏」的链路，接到我们这里只是换个输出端。

### 分级怎么读

A / B / C 是**本轮排名**，不是绝对分：A = 前 30%，这周先联系这批；B = 30%~70%，第二批；C = 其余。

报告里每个 A 级仓库都带「建议开场」，是拿他自己的证据拼出来的，别原样群发——
先把那句开场改成你自己的话，再说平台的事。

### 缓存

`.cache` 结果默认复用 12 小时（`--cache-ttl-hours`）。改过筛选规则要把脚本里的 `CACHE_VERSION` +1，
否则会读到旧结论。

## 二、联系：先贡献，再邀请

顺序不能反。上来就邀请注册，对方的默认判断是「又一个要我去注册的平台」。

1. **先在他的仓库里提一个真实改动**，哪怕只有一个文件。参考
   [`pomodoro-dual`](./pomodoro-dual/) 那次的三个 commit：暴露只读快照 → 加第二块屏 → 可选的分级刷新。
   改动小、边界清楚、默认关闭，不改变他原有行为。
2. **PR 描述里只放一条身份链接**（项目主页），不要堆功能列表和二维码。
3. **作者回复后再提平台**。这时他知道你不是来搬代码的，才愿意听「上架」这件事。
4. **对方明确说 NO 就停**，不要追问第二次。

反面清单：群发模板、催 merge、把对方代码整段复制进自己产品、在 issue 里贴广告。

### 半自动邀请：`scripts/invite_eink_authors.py`

筛选之后的动作是「一个个发消息」，这件事可以机械化，但不能全自动。原因是硬的：
GitHub 可接受使用政策把**批量未经请求的招揽**列为滥用。一天给几十个仓库开 issue，
从轻到重是：限流 → 账号被标 spam、issue 被批量关闭 → 身份被挂起。而我们这个账号
刚在上游提了真 PR #3 和 issue #4，那是能长期带流量的东西，不能拿去赌。

所以脚本这样切：

| 环节 | 谁做 | 说明 |
| --- | --- | --- |
| 找人、查资格、拼证据、写草稿、去重、记账 | 脚本 | 一次跑完十几份，每份都基于他自己仓库里的真实文件 |
| 读一遍、改开场、决定发不发 | 人 | 原样群发是最容易被识破的方式 |
| 发 | 人按一次键，脚本执行 | 每次 ≤ 3 条、每天 ≤ 5 条、同一作者只发一次 |

```bash
python scripts/invite_eink_authors.py --limit 12            # 只出草稿（默认，不发）
python scripts/invite_eink_authors.py --send --max-per-run 3
python scripts/invite_eink_authors.py --send --only owner/name
python scripts/invite_eink_authors.py --decline owner/name   # 对方说「不用了」
python scripts/invite_eink_authors.py --send --test-repo you/sandbox   # 验证 token 与链路
```

内置五道保险：

1. **链接先探活**：试出图页返回 404 就整体拒绝——不把坏链接贴进别人仓库（`/try` 没上线时这条会直接拦下）。
2. **发前深度查重**：`repo:X involves:upisqueen-blip` 有痕迹就跳过。pomodoro 那种「提过 PR + 留过评论」的会被认出来，不靠记忆。
3. **同作者只发一次**：一个人有五个墨水屏仓库，也只打扰一次。
4. **次数硬顶**：每次 3、每天 5，账落在 `output/eink-scan/outreach-state.json`，删了才会重发。
5. **标出「有 issue 模板 / 开了 Discussions」**：这类仓库建议改发 Discussion 或先看模板，自由格式 issue 会被 bot 自动关掉。

草稿本身的结构是固定的（`Hi,` → 一句只针对他的观察 → 我们能给他什么 → 一句明确的可退出），
但**第一句必须换成你自己的话**。文件头注释里带着他的证据（驱动文件路径、近半年提交数），
改这句话的时候照着写就行。

节奏：**先发 1 条，等 48 小时**。有人回、有人 star、有人来提 issue，说明话术成立，再发第二条。
没人回就改开场，不要加速——同一天发五条同样内容，等于自己举报自己。

> 名单里标「厂商账号（同行）」的（trmnl、Inkplate、Waveshare 这类）不要发。他们不是想找地方
> 上架的作者，而是同样在卖设备的人。给同行发「来我们社区上架」既不礼貌，也浪费每日额度。

## 三、邀请上架：把「接入」压到 30 秒

对方决定试，第一步不该是注册。产品侧的漏斗口是 **`/try`（零注册试出图）**：

- 打开就能填一段 JSON，立刻看到 A / B 两屏的真实出图（与固件同一套渲染代码，不是效果图）；
- 同时给出契约校验结论，缺什么字段当场说清楚；
- 觉得可以，再点「注册创作者」进沙箱，拿 token、绑设备、推送。

链路：`/try` 试出图 → `/developer` 注册 → 建沙箱应用 → 签发 App Token → 用户扫码确权 → 推送。

给对方的说明里可以只用这一句：**「平台只做三件事：确认这是谁的数据、收下你算好的结果、渲染到双屏。
取数和算法都留在你那边。」**

## 四、上线之后

- 上架 = 进入内容库，用户在设备上能选到；**作者保留自己仓库的著作权**，平台只承载设备端呈现。
- 前两周盯三件事：有没有真实推送、有没有失败回执、画面上屏效果是否和预览一致。
- 数据好的（用户留存 / 主动刷新频次高）优先谈深度合作；数据差的先改版式，别急着谈钱。
- 订阅分成在规则定下来之前，一律回答「规则另发」，不要口头承诺比例。

## 五、节奏

| 周期 | 动作 |
| --- | --- |
| 每月 1 次 | 跑一次脚本，更新名单，淘汰已停更 / 已联系过的人 |
| 每周 3~5 个 | 选 A 级里的 3~5 个，各提一个真实 PR 或 issue |
| 有回复后 48h 内 | 邀请进 `/try`，附一条针对他项目的具体建议 |
| 每季度 | 复盘：发出的 PR 合并率、上架转化率、上架后真实使用率 |
